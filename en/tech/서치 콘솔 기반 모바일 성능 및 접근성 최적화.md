# Optimizing Mobile Performance and Accessibility Based on Search Console

After observing degraded performance and accessibility metrics for the blog's mobile pages in Google Search Console's PageSpeed report, I proceeded with refactoring for improvement. This document is a troubleshooting log detailing the process from problem diagnosis to resolution.

### 1. Mobile Performance (PageSpeed) Optimization

The biggest issue was degraded loading performance in mobile environments. After analyzing the causes, I focused on improving the following three items.

#### **Eliminating Redirects and Double Loads Caused by Measurement Bots**
When performance measurement tools like Lighthouse or PageSpeed bots accessed the site, unnecessary redirects occurred due to specific logic, causing the page to load twice. This directly negatively impacted the measurement scores.
*   **Action**: Modified the crawler identification regex to exception-handle `Chrome-Lighthouse` and `PageSpeed` bots, treating them the same as regular user traffic. This eliminated unnecessary reloads and enabled accurate performance measurement.

#### **Improving TBT (Total Blocking Time) through GA4 Script Lazy Loading**
The Google Analytics 4 script was a key cause of increased Total Blocking Time (TBT) by blocking the main thread during initial rendering.
*   **Action**: Delayed the loading of the GA4 script until the user's first interaction (`scroll`, `touchstart`) or after 5 seconds if no interaction occurred. This asynchronous load transition alone successfully **reduced TBT to 0ms**.

#### **Lazy Loading Components Using IntersectionObserver**
Heavy components not essential for initial rendering, such as the Giscus comment section and WebGL canvas, hindered loading speed.
*   **Action**: Implemented `IntersectionObserver` API to load these components only when they enter the viewport.
*   **Further Optimization**:
    *   Paused the `requestAnimationFrame` loop when the WebGL canvas moved out of view to prevent unnecessary resource usage.
    *   Set `min-height: 150px` on the Giscus comment section container to prevent layout shifts (CLS, Cumulative Layout Shift) that would occur after component loading.

### 2. Achieving 100% WCAG 2.1 AA Accessibility Standards

Improved to fully meet Web Content Accessibility Guidelines (WCAG 2.1 AA) so that all users can access content equally.

*   **Improved Color Contrast**: The previous accent orange color had low contrast, reducing text readability. It was replaced with the following colors that pass WCAG standards (4.5:1 or higher):
    *   **Light Mode**: `#c2410c` (Contrast ratio 4.7:1)
    *   **Dark Mode**: `#fb923c` (Contrast ratio 5.8:1)
*   **Ensured Touch Target Area**: Increased the minimum clickable area for buttons and links to **44px × 44px** or more in mobile environments to improve ease of operation.
*   **Assigned ARIA Attributes**: Added ARIA (Accessible Rich Internet Applications) attributes to help assistive technologies like screen readers clearly interpret the meaning of content.
    *   WebGL Canvas: `role="img"`
    *   Giscus Comment Area: `role="region"`
    *   RSS Icon Link: Provided a text label for screen readers

### 3. Multilingual SEO and Structure Improvement

*   **Dynamic Sidebar Menu Generation**: Previously, sidebar menus were generated based on filenames, causing titles to display incorrectly in multilingual environments. The `getBlogSidebar()` function was modified to read the `title` value defined in each document's Frontmatter instead of the filename, allowing menus to be dynamically generated according to language settings.
*   **SEO Structuring**: Standardized the use of only one `<h1>` tag at the top of all documents and improved the structure to clearly convey freshness signals to search engines by explicitly stating an `Updated Date` timestamp at the bottom of the content.
