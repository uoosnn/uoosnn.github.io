# 15年ぶりのノートPC導入記：VMボトルネック脱出とRyzen 8C/16T開発マシンの構築

::: tip コアインサイト
15年間維持してきたデスクトップVM環境のI/O遅延とビルド待ちから脱出するため、**AMD Ryzen 7 8840HS (8コア/16スレッド) + Radeon 780M + LPDDR5x搭載の超軽量開発ノートPC**を導入し、WSL2/Dockerネイティブワークロードを最適化した記録。
:::

## 1. 従来のVM(仮想マシン)開発環境の限界

* **I/Oおよびパッケージインストールのボトルネック**: `npm install`やDockerレイヤービルド時の仮想ディスクオーバーヘッドによる待ち時間増大。
* **コンテキストスイッチ遅延**: VS Code、Docker、ブラウザ20タブ以上を開いた際のVMメモリスワップ発生。

---

## 2. ハードウェアスペックと開発負荷のマッピング

| コンポーネント | 選定スペック | 開発ワークフローへの貢献 |
| :--- | :--- | :--- |
| **CPU** | AMD Ryzen 7 (8C / 16T) | VitePress SSGビルドおよびVite HMRの完全ゼロ遅延 |
| **GPU** | AMD Radeon™ 780M (RDNA 3) | WebGL 3DキャンバスおよびThree.jsの快適な描画 |
| **Memory** | 16GB LPDDR5x (広帯域) | Docker + Node.js + VS Codeの並行マルチタスク |
| **Storage** | 512GB PCIe 4.0 NVMe SSD | git checkoutおよびパッケージI/O待ち時間の完全消滅 |
| **Display** | 14" WUXGA 16:10 (1920x1200) | 16:9比率に比べコード行を縦に15%多く表示 |
| **Mobility** | 1.38kg / 65W USB-PD | 場所を選ばず即座に開発セッションを継続 |

---

## 3. コアチェックポイント (Gotchas)

1. **Windows 11 WSL2メモリ制限設定**: WSL2はデフォルトでホストRAMの50%を専有するため、`%USERPROFILE%\.wslconfig`で`memory=8GB`および`processors=8`を指定しリソース配分を最適化する。
