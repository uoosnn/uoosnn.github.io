# AIと協業する開発者のための3大エンジニアリング安全原則

::: tip コアインサイト
AIコーディングツールの爆発的な生産性は、**(1) ジュニア開発者のPRと同等の厳格なコード監査、(2) アトミックなGitコミットによるロールバック安全網、(3) テストコード先行の検証(TDD)**という3大安全装置が機能して初めて持続可能な技術資産となる。
:::

## 1. 原則1: AI生成コードは「新入社員のPR」として監査する
* 1行でも理解できないコードはメインブランチへマージしない。
* メモリリーク、SQLインジェクション、npm/PyPI実在性を必ず検証。

## 2. 原則2: すべてのAI実験はアトミックGitコミットで隔離する
```bash
git checkout -b feature/ai-refactor
git commit -m "chore: checkpoint before AI refactoring"
# 障害時は即座に1秒ロールバック
git reset --hard HEAD~1
```

## 3. 原則3: コード生成前に「単体テストコード」を先に定義する
* 入力値、戻り値、例外系(Null, Timeout, Boundary)を定義したテストコードを先に生成させ、それを100%パスする実装コードを書かせる。
