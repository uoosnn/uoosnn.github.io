# ログなしApache SSLエラー、straceで分析したトラブルシューティング


## 問題状況: 音もなく失敗するApacheの実行

SSL証明書の更新作業後、Apacheウェブサーバーが起動しない現象が発生しました。一般的な障害状況とは異なり、特異な点は以下の通りでした。

1.  **設定ファイルの構文エラーなし**: `httpd -t`コマンドで設定ファイル(`httpd.conf`)の有効性を検証した際、`Syntax OK`と正常な応答が得られました。
2.  **エラーログの不在**: メインのエラーログファイル(`/var/log/httpd/error_log`)には、いかなるエラー記録も残っていませんでした。

サービスは実行されないのに、原因を特定する手がかりが全くない「サイレントフェイル」状況でした。このような場合、プロセスレベルの動作を追跡するために、システムコールを追跡する`strace`を使用することにしました。

## 原因分析: straceによるシステムコール追跡

以下のコマンドを使用して、Apacheデーモンがフォアグラウンドモード(`-X`)で実行される際のシステムコールを追跡しました。

```bash
# strace /usr/sbin/httpd -X 2>&1 | tail -n 50
```

`strace`出力の最後の50行で、プロセスが終了する直前の挙動を捉えることができ、これはSSL秘密鍵の処理過程で致命的なエラーが発生したことを明確に示していました。

### 1. SSLパスフレーズ処理過程

```c
pipe([206, 207]) = 0
clone(...) = 2834
read(206, "8", 1)
read(206, "0", 1)
...
read(206, "\n", 1)
```

ログの最初の部分で、Apacheは`pipe`と`clone`システムコールを通じて子プロセスを生成しました。これは、`httpd.conf`に設定された`SSLPassPhraseDialog`ディレクティブに従い、暗号化された秘密鍵のパスワードを外部スクリプトから受け取るためのプロセスです。`read`システムコールを通じてパイプからパスワード文字列を正常に受信したことを確認できます。

### 2. 秘密鍵ファイルのロード

```c
open("/etc/httpd/ssl/key.pem", O_RDONLY) = 203
read(203, "-----BEGIN RSA PRIVATE KEY-----\r"..., 4096) = 1781
```

パスワードを確保したApacheプロセスは、`open`システムコールで該当する仮想ホストの秘密鍵ファイル(`key.pem`)を開き、`read`を通じてファイルの内容をメモリにロードしました。ここまでは正常な流れでした。

### 3. エラー発生とプロセス終了

```c
write(46, "[Thu May 21 05:31:27 2026] [erro"..., 63) = 63
... (総8行のエラー記録) ...
exit_group(1)
```

問題はこの次の段階で発生しました。Apacheは、メモリに読み込んだ秘密鍵を、先に渡されたパスワードで復号化するか、復号化された鍵を証明書(`cert.pem`)と比較して有効性を検証する過程で失敗しました。

注目すべき点は、`write`システムコールの最初の引数であるファイルディスクリプタ(File Descriptor)が`46`であるという点です。これは標準エラー(`stderr`, fd 2)ではなく、該当する仮想ホストに指定された個別のエラーログファイルでした。つまり、Apacheは**メインのエラーログではなく、特定の仮想ホストのログファイルにのみエラーを記録**した後、エラーコード`1`とともに`exit_group(1)`システムコールを呼び出して、自らプロセスを終了させていたのです。これがメインのエラーログに何の痕跡もなかった理由です。

## 結論と解決

`strace`ログ分析を通じて、問題の根本原因を次の2つのシナリオに絞り込むことができました。

1.  **秘密鍵パスワード(Passphrase)の不一致**: 新しく発行された`key.pem`ファイルのパスワードが変更されたか、削除されたにもかかわらず、`SSLPassPhraseDialog`スクリプトが以前のパスワードを渡し、復号化に失敗した。
2.  **証明書と秘密鍵のペアの不一致**: 秘密鍵は正しいパスワードで復号化されたが、一緒に設定された証明書ファイルとペアが一致しない場合。(つまり、両ファイルのモジュラスハッシュ値が異なる)

この分析に基づき、新しく発行された証明書と秘密鍵が正確に一致するかを`openssl`コマンドでモジュラス値を比較して確認し、パスワードが設定された鍵であれば`SSLPassPhraseDialog`設定が正しい値を返すかを検証しました。最終的に正しい証明書/鍵ペアを適用し、Apacheを再起動して問題を解決しました。

今回のトラブルシューティングは、ログファイルに手がかりが残らない障害状況において、`strace`のようなシステムレベルのデバッグツールがいかに強力であるかを改めて確認する機会となりました。
