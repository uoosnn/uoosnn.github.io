# VitePressベースの静的ブログにおけるnpm依存関係の脆弱性分析と解決記録


### 1. 概要

プロジェクトのCI/CDパイプラインの定期点検中に、VitePressベースの静的ブログのnpm依存関係から多数のセキュリティ脆弱性が発見されました。最終的なデプロイ成果物は純粋な静的ファイル（HTML/CSS/JS）ですが、ビルドおよび開発環境における潜在的な脅威を排除するため、分析と対応を進めました。

### 2. 脅威分析: 静的サイトとビルド環境の脆弱性

初期分析段階で、「静的サイトのnpm脆弱性が実際のランタイム環境に脅威となるのか？」という疑問を検討しました。

-   **ランタイム環境**: 最終ユーザーがブラウザからアクセスするデプロイ済みの静的ファイル環境では、サーバー側のコードは実行されないため、権限奪取などの直接的な攻撃は不可能です。危険度はほとんどありません。
-   **ビルド/開発環境**: しかし、脅威はランタイムではなく、別の段階に存在しました。
    1.  **CI/CD環境 (GitHub Actions)**: 悪意のあるコードを含む脆弱なパッケージは、ビルドコンテナ内部で実行される際、環境変数として保存された`Secrets`（デプロイキー、APIトークンなど）にアクセスして奪取する可能性があります。
    2.  **ローカル開発環境**: 開発者のPCで`npm run dev`実行時、パス・トラバーサル（Path Traversal）のような脆弱性を介して、ローカルファイルシステムの機密情報が流出する可能性があります。

結論として、ランタイムの安全性とは別に、ビルドチェーン自体のセキュリティのために`npm audit`による脆弱性管理は必須であると判断しました。

### 3. 脆弱性スキャンおよび分析結果

プロジェクトルートで`npm audit`コマンドを実行し、依存関係パッケージをスキャンしました。

```bash
npm audit
```

合計6件の脆弱性が報告され、深刻度「High」ランクの主要な脆弱性は以下の通りです。

| パッケージ名          | 深刻度 | 脆弱性タイプ (CWE) | 内容                                                                |
| ----------------- | ------ | ----------------- | ------------------------------------------------------------------- |
| `brace-expansion` | High   | CWE-400           | サービス拒否(DoS)攻撃。操作された入力により過度なリソースを消費させる可能性があります。 |
| `postcss`         | High   | CWE-22            | パス・トラバーサル（Path Traversal）攻撃。.mapファイルロード時に任意のファイルにアクセス可能。 |
| `vite`            | High   | CWE-22, CWE-522   | Windows環境でNTLMv2ハッシュ（パスワード）漏洩の可能性。               |

### 4. 解決過程

#### 4.1. 自動パッチ適用

`npm audit fix`コマンドを使用して、SemVer互換性を維持する範囲内で脆弱性が解決されたバージョンへの自動更新を試みました。

```bash
npm audit fix
```

このコマンドにより、3件の「High」ランクの脆弱性が直ちに解決されました。この過程で更新された依存関係情報は`package-lock.json`ファイルに反映されました。

#### 4.2. CI/CDパイプライン反映の重要性

CI/CD環境（GitHub Actions）では、ビルドの一貫性と速度のために`npm install`の代わりに`npm ci`を使用するのが一般的です。`npm ci`は`package.json`を参照するのではなく、`package-lock.json`に明記された正確なバージョンのパッケージのみをインストールします。

したがって、ローカル環境で`npm audit fix`を通じて`package-lock.json`を更新し、これをリモートリポジトリにプッシュして初めて、CI/CDパイプラインでも安全なバージョンのパッケージを使用してビルドが実行されます。この過程を怠ると、パイプラインは引き続き脆弱な旧バージョンのパッケージを使用することになるため、`package-lock.json`のコミットおよびプッシュは必須の後続措置です。

#### 4.3. 未解決の脆弱性処理

`npm audit fix`実行後も、`vite`と`esbuild`関連の一部の脆弱性は「No fix available」の状態のままでした。これは、当該脆弱性を解決するためにメジャーバージョンアップが必要であるか、上位依存関係パッケージがまだパッチをリリースしていないためです。

この場合、強制的にバージョンを修正して他のパッケージとの互換性を損なうリスクを冒すよりも、VitePressの公式リリースで当該依存関係が更新されるのを待つことにしました。

### 5. 結論

静的サイトであっても、ビルドおよび開発環境のセキュリティは重要であり、定期的な`npm audit`点検は必須です。`npm audit fix`を通じて直ちに解決可能な脆弱性をパッチし、変更された`package-lock.json`をリモートリポジトリに反映することで、CI/CDパイプラインのセキュリティレベルを強化しました。
