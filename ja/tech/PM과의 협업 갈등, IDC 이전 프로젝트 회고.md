# IDC物理移設後のLenovoサーバーXCCアクセス不能障害とシリアルコンソール現場トラブルシューティング回顧

::: tip 1行要約
データセンター物理移設直後、管理ネットワーク未開通によりLenovo XCC(IPMI/BMC) Webコンソールへアクセスできずパスワードポリシー競合が発生した際、**シリアルコンソール(Serial Console)を用いた低水準BIOS直結操作**でサーバーOS稼働を最優先確保した実戦事例。
:::

## 1. インフラ移設の概要と現場ボトルネック

物理サーバーを新外部IDCラックへ移設・マウントした直後、運用引き継ぎで深刻な障害が発生。

```
[移設現場のボトルネック]
ラックマウント完了 ──> [管理網未開通] ──✖ [XCC Webコンソール接続不可]
                              │
                      (代替経路投入) ──> [シリアルコンソール (Serial Cable)] ➔ BIOS直接制御
```

* **障害事象**: 移設先IDC運用チームがサーバー遠隔管理インターフェース(Lenovo XCC)にログインできないと報告。
* **背景**: 移設前の現場ログイン失敗を防ぐため標準パスワードへ事前初期化していたが、受け入れ側IDCのセキュリティポリシーと競合。
* **現場制約**: Out-of-Band管理ネットワークが未開通のため、Webコンソールからの設定変更が不可能な孤立状態。

---

## 2. 現場トラブルシューティング：シリアルコンソールへの切り替え

遠隔PMはWebコンソール復旧を試み続けたが、現場では不可能な作業であったため優先順位を再定義した。

1. **OS稼働の最優先化**: XCC Web復旧は後回しにし、サービス本体のOS起動を最優先目標に設定。
2. **シリアルコンソール直結**: サーバー背面のシリアルポートにコンソールケーブルを直結(`Baud rate: 115200`)。
3. **低水準BIOS制御**: BIOS画面からRAIDコントローラー状態、ブート順序、NICリンクを確認しOS起動を完了。
4. **結果**: 移設メンテナンス時間枠内でサーバー起動を完了し、後日管理網開通時にXCCを再設定。

---

## 3. コアチェックポイント (Gotchas)

1. **OOB管理網の事前開通**: サーバー移設時はサーバー本体の設置前に管理用スイッチとIPプールが開通しているか確認が必須。
2. **シリアルケーブルの現場必携**: ネットワーク完全孤立時の最後の生命線はシリアルコンソールであるため、現場必須携行品に指定する。
