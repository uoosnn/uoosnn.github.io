# レガシーサーバーの段階的マイグレーションプロセス


古いレガシーサーバーを最新の環境に移行する作業には、多くの変数と複雑さが伴います。この記事では、旧式のMySQLおよびPHP環境で運用されていたサーバーを、最新のOSとMariaDBに移行するための段階的なマイグレーションプロセスと、主な考慮事項についてまとめます。

## マイグレーション前の主な考慮事項

本格的な移行に先立ち、必ず確認し、お客様と協議すべき2つの重要な事項があります。

### PHPのアップグレードとウェブソース
サーバー環境がアップグレードされると、既存のウェブソース(PHP)が正常に動作しない可能性があります。最新のPHPバージョンに合わせて既存のコードを修正する作業は、サーバーマイグレーションのサポート範囲に含まれず、これはお客様自身で対応していただく部分です。

### データベース(DB)のマイグレーションパスとコスト
現在使用中のMySQL 5.1バージョンからターゲットバージョンであるMariaDB 11.4.2へ直接アップグレードすることは不可能です。データの整合性と安定性を保証するため、以下のような多段階のマイグレーションプロセスを経る必要があります。

```
mysql 5.1 -> 5.5 -> 5.7 -> 8.0 -> mariadb 10.x -> mariadb 11.4.2
```

このように合計5段階のアップグレードを順次進める必要があるため、かなりの作業時間とコストが発生する可能性があります。

## 4段階のマイグレーション実行手順

安全な移行のため、次のような4段階の手順でマイグレーションを進めます。

### ステップ1：臨時サーバーの構築
まず、お客様が希望する最新仕様で臨時サーバーを準備します。最新のOS（例：Rocky Linux 9.x）とサービスバージョン（MariaDB 11.4.2など）をインストールし、エンジニアがサービス連携作業を行います。

### ステップ2：データ同期とテスト
元サーバーのすべてのデータ（ウェブソース、DBデータなど）を構築された臨時サーバーにコピー（Sync）します。エンジニアはデータが正常にインポートされたかを確認し、サービスが正常に動作するかを複数回テストします。その後、お客様が直接テストを行えるよう、ローカル環境で確認する方法を案内します。

### ステップ3：修正と再確認（n次移行）
お客様がテスト過程で発見した機能の問題やイシューを伝えると、エンジニアがその内容を修正・補完します。サービスが安定するまで、このプロセスは何度も繰り返されることがあります。

### ステップ4：最終移行
お客様からすべての機能が正常に動作するという最終確認を受けた後、最終移行作業を開始します。

*   **サービス停止：** 最終移行中は、データ損失を防ぎ、完全なデータ整合性を確保するため、元サーバーのウェブおよびDBサービスをすべて停止します。
*   **最終データ同期：** サービスが停止した状態で、元サーバーのDBデータを臨時サーバーに再度コピーします。
*   **IP切り替え：** データ同期が完了したら、元サーバーと臨時サーバーのIPを互いに切り替え、サービストラフィックが新しいサーバーに向かうようにします。

この最終移行作業は平均で4〜5時間かかり、予期せぬ特異事項が発生した場合は、さらに時間がかかることがあります。
