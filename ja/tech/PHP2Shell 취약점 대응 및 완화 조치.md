# PHP2Shell 脆弱性(CVE-2026-109619)への対応と緩和策

::: tip 1行まとめ
PHPでメモリ不足(OOM)発生時に`longjmp()`によってリクエストが中断され、内部リクエストデータが初期化されないために発生する脆弱性(CVE-2026-109619, CVE-2026-109618)です。根本的な解決にはパッチバージョンのアップグレードが必須であり、即時パッチ適用が不可能な環境では、php.iniおよびPHP-FPMワーカーの再利用設定、リクエストボディサイズ制限、WAFルールの適用により攻撃対象領域を縮小する必要があります。
:::

## 脆弱性の発生原因

CVE-2026-109619およびCVE-2026-109618（通称PHP2Shell）脆弱性の根本原因は、PHPエンジンがメモリ不足（Out of Memory, OOM）エラーを処理する過程における欠陥にあります。

エラー発生時、PHPは`longjmp()`関数を呼び出して現在のリクエスト処理を異常終了させます。この過程で内部リクエストデータが完全に初期化されず、メモリ上に残存します。その後、同じワーカープロセスが次のリクエストを処理する際、以前に汚染された内部状態がそのまま再利用され、リモートコード実行などの深刻なセキュリティ問題につながる可能性があります。

EOL(End of Life)を迎えたPHP 5.xなどのレガシーバージョンを使用しているサーバーが主に影響を受け、根本的な解決策はサポートされているバージョンへのアップグレードです。

## 段階的な緩和策

PHP開発チームとセキュリティ業界は、設定変更のみで攻撃を完全に遮断することは不可能であるため、パッチバージョンへのアップグレードを唯一の根本的な解決策として推奨しています。即時アップデートが困難な環境では、以下の4つの暫定的な緩和策を組み合わせて攻撃対象領域を減らす必要があります。

### 1. PHPおよびPHP-FPMの設定変更

セッションアップロードの進行機能と自動開始を無効化し、OOMによって汚染されたワーカープロセスが再利用されないよう、リクエスト1回処理後にプロセスを再生成するように強制します。

- **php.ini設定**
```ini
session.upload_progress.enabled = 0
session.auto_start = 0
```

- **www.conf (PHP-FPM)設定**
```ini
pm.max_requests = 1
```

### 2. Webサーバーのリクエストボディサイズ制限

攻撃者が大容量のペイロードを送信して意図的にメモリ枯渇(OOM)を誘発するのを阻止するため、Webサーバー側で許可するリクエストボディサイズをサービスに必要な最小値に制限します。

- **Nginx (nginx.conf)**
```nginx
client_max_body_size 1m; # サービス特性に合わせた最小サイズに制限
```

- **Apache (httpd.conf または .htaccess)**
```apache
LimitRequestBody 1048576 # 1MB
```

### 3. WAFマネージドルールの適用

利用中のクラウドおよびネットワークファイアウォール(WAF)で配布されているPHP2Shell専用の緊急遮断ルールを有効化し、異常なペイロードを事前にフィルタリングします。

- **対象サービス**: AWS WAF, Cloudflare, Google Cloud Armorなど、各ベンダーのマネージドルールセットの更新を確認し、即座に適用します。

### 4. サードパーティ製アプライアンスの点検

一般的なWebサーバーだけでなく、内部管理インターフェースなどにPHPを内蔵して使用するサードパーティ製アプライアンス機器も、同様の脆弱性の影響を受ける可能性があります。

- **点検対象**: Palo Alto Networks(PAN-OS), Siemensなど、PHPを内蔵したネットワークおよびセキュリティ機器
- **対処方法**: 各メーカーのセキュリティアドバイザリを確認し、専用のホットフィックスを適用する必要があります。

## 重要なチェックポイント (Gotchas)

- **一時的な対策によるパフォーマンスへの影響を考慮**: PHP-FPMで`pm.max_requests = 1`を適用すると、リクエストごとにワーカープロセスが再生成されるため、CPUオーバーヘッドと応答遅延が発生する可能性があります。これは一時的な防御策としてのみ維持し、速やかにコアパッチを適用する必要があります。
- **レガシーバージョン(PHP 5.x)の限界**: 公式セキュリティサポートが終了したPHP 5.xバージョンでは公式パッチが提供されないため、一時的な緩和策適用後、PHP 8.xなどのサポートバージョンへの移行が必須です。
- **アプライアンス機器の見落としに注意**: 自社で構築したWebサーバー以外に、PAN-OSなどのサードパーティ製セキュリティ/ネットワーク機器に内蔵されたPHPエンジンがセキュリティの死角になりやすいため、資産リストに基づいた全数点検が必要です。
