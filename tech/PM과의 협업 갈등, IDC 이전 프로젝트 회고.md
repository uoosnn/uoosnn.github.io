# IDC 이전 후 Lenovo 서버 XCC 접근 불가 이슈 및 현장 트러블슈팅 회고

::: tip 1줄 요약
물리적 IDC 이전 직후 네트워크 미연결로 Lenovo XCC(IPMI/BMC) 웹 콘솔 접근이 불가능하고 관리자 패스워드 정책이 충돌할 때, **직렬 콘솔(Serial Console)을 통한 저수준 BIOS 직결 작업**으로 OS 가용성을 먼저 확보하여 작업 지연을 방어한 실전 사례.
:::

## 1. 인프라 이설 개요

기존 데이터센터의 레거시 물리 서버들을 신규 외부 IDC로 이설하여 랙 마운트 및 전원/네트워크 인계를 진행했다.

```
[인프라 이설 현장 병목]
타겟 IDC 랙 장착 ──> [네트워크 미개통] ──✖ [XCC 웹 콘솔 접근 불가]
                             │
                      (대체 경로 투입) ──> [직렬 콘솔 (Serial Console)] ➔ BIOS 직접 제어
```

## 2. 장애 현상: XCC 원격 관리 콘솔 잠김 & 정책 충돌

* **현상**: 타겟 IDC 운영팀이 서버의 원격 관리 인터페이스인 **Lenovo XCC(XClarity Controller)** 웹 GUI에 로그인할 수 없다고 통보.
* **배경**: 이설 전 현장 로그인 실패 변수를 없애고자 사전 표준 패스워드로 초기화해 두었으나, 인계받는 IDC 운영팀의 내부 보안 정책과 충돌하여 로그인이 거부됨.
* **현장 제약**: 신규 랙의 관리망(Out-of-Band) 네트워크 라우팅이 완료되지 않아 현장 엔지니어도 XCC 웹 인터페이스에 접속할 수 없는 고립 상태.

## 3. 현장 트러블슈팅: 직렬 콘솔(Serial Console) 우회

원격지 PM은 웹 콘솔을 통한 XCC 설정 초기화를 계속 시도하려 했으나, 네트워크가 없는 현장에서는 불가능한 작업이었다.

1. **우선순위 재정의**: XCC(BMC) 웹 접근 복구는 2차 과제로 미루고, 서버 본체의 부팅 및 서비스 OS 가용성을 최우선 목표로 전환.
2. **시리얼 콘솔 직결**: 서버 후면 시리얼 포트에 콘솔 케이블을 연결하고 터미널(`Baud rate: 115200`)로 직접 진입.
3. **저수준 BIOS 설정 완료**: BIOS 레벨에서 부팅 순서, 스토리지 어레이(RAID Controller) 인식 상태, 네트워크 카드 링크를 확인하고 OS 부팅을 정상 완료.
4. **결과**: 전체 마이그레이션 다운타임 일정 내에 서버 기동을 마친 후 관리망 복구 시점에 XCC 패스워드를 재할당.

## 4. 핵심 체크포인트 (Gotchas)

1. **물리 이설 시 OOB(Out-of-Band) 관리망 사전 개통**: 서버 장착 전 IPMI/XCC용 관리망 스위치와 IP 풀이 먼저 살아있는지 확인해야 원격 콘솔 작업이 가능하다.
2. **이설 직전 시리얼 콘솔 케이블 및 젠더 준비**: 네트워크가 단절된 상황에서 서버를 살릴 수 있는 최후의 수단은 시리얼 콘솔이므로 현장 필수 지참 장비로 지정해야 한다.
3. **이종 조직 간 패스워드 인수인계 프로토콜**: 다수 벤더/운영팀이 얽힌 이전 작업에서는 패스워드 정책을 사전에 문서로 100% 합의해야 현장 대기 시간을 방지할 수 있다.
