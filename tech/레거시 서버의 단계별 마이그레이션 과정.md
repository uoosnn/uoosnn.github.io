오래된 레거시 서버를 최신 환경으로 이전하는 작업은 많은 변수와 복잡성을 동반합니다. 이 글에서는 구형 MySQL 및 PHP 환경으로 운영되던 서버를 최신 OS와 MariaDB로 이전하는 단계별 마이그레이션 과정과 주요 고려사항을 정리합니다.

## 마이그레이션 전 주요 고려사항

본격적인 이전에 앞서, 반드시 확인하고 고객과 협의해야 할 두 가지 핵심 사항이 있습니다.

### PHP 업그레이드와 웹 소스
서버 환경이 업그레이드되면 기존 웹 소스(PHP)가 정상적으로 동작하지 않을 수 있습니다. 최신 PHP 버전에 맞춰 기존 코드를 수정하는 작업은 서버 마이그레이션 지원 범위에 포함되지 않으며, 이는 고객이 직접 처리해야 할 부분입니다.

### 데이터베이스(DB) 마이그레이션 경로 및 비용
현재 사용 중인 MySQL 5.1 버전에서 목표 버전인 MariaDB 11.4.2로 직접 업그레이드하는 것은 불가능합니다. 데이터의 정합성과 안정성을 보장하기 위해 아래와 같은 다단계 마이그레이션 과정을 거쳐야 합니다.

```
mysql 5.1 -> 5.5 -> 5.7 -> 8.0 -> mariadb 10.x -> mariadb 11.4.2
```

이처럼 총 5단계의 업그레이드를 순차적으로 진행해야 하므로, 상당한 작업 시간과 비용이 발생할 수 있습니다.

## 4단계 마이그레이션 실행 절차

안전한 이전을 위해 다음과 같은 4단계 절차를 통해 마이그레이션을 진행합니다.

### 1단계: 임시 서버 구축
먼저 고객이 원하는 최신 사양으로 임시 서버를 준비합니다. 최신 OS(예: Rocky Linux 9.x)와 서비스 버전(MariaDB 11.4.2 등)을 설치하고, 엔지니어가 서비스 연동 작업을 진행합니다.

### 2단계: 데이터 동기화 및 테스트
원본 서버의 모든 데이터(웹 소스, DB 데이터 등)를 구축된 임시 서버로 복사(Sync)합니다. 엔지니어는 데이터가 정상적으로 임포트되었는지 확인하고, 서비스가 정상 동작하는지 여러 차례 테스트를 수행합니다. 이후 고객이 직접 테스트를 진행할 수 있도록 로컬 환경에서 확인하는 방법을 안내합니다.

### 3단계: 수정 및 재확인 (x차 이전)
고객이 테스트 과정에서 발견한 기능 문제나 이슈를 전달하면, 엔지니어가 해당 내용을 수정하고 보완합니다. 서비스가 안정화될 때까지 이 과정은 여러 번 반복될 수 있습니다.

### 4단계: 최종 이전
고객으로부터 모든 기능이 정상적으로 작동한다는 최종 확인을 받은 후, 최종 이전 작업을 시작합니다.

*   **서비스 중단:** 최종 이전 중에는 데이터 유실을 방지하고 완벽한 데이터 정합성을 확보하기 위해 원본 서버의 웹 및 DB 서비스를 모두 중단합니다.
*   **최종 데이터 동기화:** 서비스가 중단된 상태에서 원본 서버의 DB 데이터를 임시 서버로 다시 한번 복사합니다.
*   **IP 교체:** 데이터 동기화가 완료되면, 원본 서버와 임시 서버의 IP를 서로 교체하여 서비스 트래픽이 새로운 서버로 향하도록 전환합니다.

이 최종 이전 작업은 평균적으로 4~5시간이 소요되며, 예상치 못한 특이사항 발생 시 시간이 더 길어질 수 있습니다.
