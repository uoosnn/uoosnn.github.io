오래된 시스템은 한 회사의 역사이자 자산입니다. 하지만 기술은 끊임없이 발전하고, 언젠가는 최신 환경으로 안전하게 옮겨야 하는 시점이 찾아옵니다. 과거의 기술과 현재의 기술을 모두 이해하고 미래로 안전하게 인도하는 '레거시 엔지니어'로서, 수많은 경험을 통해 정립한 체계적이고 안전한 서버 이전 가이드를 공유합니다.

## 이전 전, 반드시 확인해야 할 중요 안내사항

성공적인 이전을 위해서는 '새 집'을 짓는 것만큼이나 기존 '가구'의 상태를 파악하고, 이사 계획을 명확히 공유하는 것이 중요합니다. 본격적인 작업에 앞서 고객과 반드시 협의해야 할 두 가지 핵심 사항이 있습니다.

### 1. 웹 소스(PHP)는 직접 수정해야 합니다.

저희의 역할은 튼튼하고 안정적인 새 서버(새 집)를 구축하고 데이터를 옮겨드리는 것입니다. 하지만 기존에 사용하던 웹 소스(가구)가 새 서버 환경과 맞지 않을 수 있습니다. 특히 PHP 버전을 업그레이드할 경우, 기존 코드가 정상적으로 동작하지 않아 수정이 필요할 수 있습니다.

이러한 애플리케이션 코드 수정은 저희의 지원 범위를 벗어나므로, 고객께서 직접 처리해주셔야 합니다.

### 2. 데이터베이스는 5단계의 마이그레이션이 필요합니다.

현재 사용 중인 MySQL 5.1 버전은 너무 오래되어 최신 버전인 MariaDB 11.4.2로 한 번에 이전할 수 없습니다. 마치 구형 스마트폰의 데이터를 여러 번의 중간 단계를 거쳐 최신폰으로 옮기는 것과 같습니다.

안전한 데이터 이전을 위해 아래와 같이 총 5단계의 순차적인 마이그레이션을 거쳐야 합니다.

- **마이그레이션 경로:** `MySQL 5.1` → `5.5` → `5.7` → `8.0` → `MariaDB 10.x` → `MariaDB 11.4.2`

이처럼 여러 단계를 거쳐야 하므로 상당한 시간과 비용이 발생할 수 있다는 점을 미리 안내해 드립니다.

## 안전한 서버 이전 절차 (4단계)

서비스 중단을 최소화하고 데이터 유실 없이 안전하게 이전하기 위해 다음과 같은 4단계 절차를 따릅니다.

### 1단계: 임시 서버 구축 (모델하우스 짓기)

먼저 고객이 원하는 최신 OS(예: Rocky Linux 9.x)와 서비스 버전을 설치하여 '모델하우스' 역할을 할 임시 서버를 구축합니다. 이후 엔지니어가 웹, DB 등 필요한 모든 서비스가 완벽하게 연동되도록 설정합니다.

### 2단계: 데이터 동기화 및 테스트 (가구 옮겨보고 테스트하기)

원본 서버의 모든 데이터(웹 소스, DB 데이터 등)를 임시 서버로 복사합니다. 엔지니어는 데이터가 정상적으로 옮겨졌는지 확인하고, 고객이 직접 서비스를 테스트할 수 있도록 로컬에서 확인하는 방법을 안내해 드립니다. 고객은 이 단계에서 기능이 정상적으로 동작하는지 꼼꼼히 확인할 수 있습니다.

### 3단계: 반복 테스트 및 수정 (인테리어 수정하기)

고객이 테스트 과정에서 발견한 기능 문제나 이슈를 전달해주시면, 엔지니어가 즉시 수정 작업을 진행합니다. 고객이 "이제 완벽하다"고 확인할 때까지 이 테스트와 수정 과정은 여러 번 반복될 수 있습니다.

### 4단계: 최종 이전 (간판 바꿔 달기)

모든 기능이 정상임을 고객으로부터 최종 확인받으면, 실제 이전을 시작합니다.

- **서비스 중단:** 데이터가 뒤섞이는 것을 방지하기 위해, 최종 데이터 동기화 전 원본 서버의 웹 및 DB 서비스를 완전히 중단합니다. 이 시간에는 사이트 접속이 불가능합니다.
- **최종 데이터 복사:** 서비스가 중단된 상태에서 원본 서버의 DB 데이터를 다시 한번 임시 서버로 복사하여 최신 상태로 맞춥니다.
- **IP 교체:** 데이터 복사가 완료되면, 원본 서버와 임시 서버의 IP 주소를 서로 맞바꿉니다. 이로써 모든 사용자는 새로운 서버로 접속하게 됩니다.

이 최종 이전 작업은 **평균 4~5시간**이 소요되며, 예상치 못한 특이사항 발생 시 시간이 더 길어질 수 있습니다.
