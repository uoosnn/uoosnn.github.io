# VitePress 기반 정적 블로그의 npm 의존성 취약점 분석 및 해결 기록


### 1. 개요

프로젝트 CI/CD 파이프라인의 정기 점검 중, VitePress 기반 정적 블로그의 npm 의존성에서 다수의 보안 취약점이 발견되었다. 최종 배포 산출물은 순수 정적 파일(HTML/CSS/JS)이지만, 빌드 및 개발 환경의 잠재적 위협을 제거하기 위해 분석 및 대응을 진행했다.

### 2. 위협 분석: 정적 사이트와 빌드 환경의 취약점

초기 분석 단계에서 "정적 사이트의 npm 취약점이 실제 런타임 환경에 위협이 되는가?"라는 질문을 검토했다.

-   **런타임 환경**: 최종 사용자가 브라우저에서 접근하는 배포된 정적 파일 환경에서는 서버 측 코드가 실행되지 않으므로, 권한 탈취 등의 직접적인 공격은 불가능하다. 위험도는 거의 없다.
-   **빌드/개발 환경**: 하지만 위협은 런타임이 아닌 다른 단계에 존재했다.
    1.  **CI/CD 환경 (GitHub Actions)**: 악의적인 코드가 포함된 취약한 패키지는 빌드 컨테이너 내부에서 실행될 때, 환경 변수로 저장된 `Secrets` (배포 키, API 토큰 등)에 접근하여 탈취할 수 있다.
    2.  **로컬 개발 환경**: 개발자 PC에서 `npm run dev` 실행 시, 경로 횡단(Path Traversal)과 같은 취약점을 통해 로컬 파일 시스템의 민감한 정보가 유출될 수 있다.

결론적으로, 런타임의 안전성과 별개로 빌드 체인 자체의 보안을 위해 `npm audit`을 통한 취약점 관리는 필수적이라고 판단했다.

### 3. 취약점 스캔 및 분석 결과

프로젝트 루트에서 `npm audit` 명령을 실행하여 의존성 패키지를 스캔했다.

```bash
npm audit
```

총 6건의 취약점이 보고되었으며, 심각도 'High' 등급의 주요 취약점은 다음과 같다.

| 패키지명          | 심각도 | 취약점 유형 (CWE) | 내용                                                                |
| ----------------- | ------ | ----------------- | ------------------------------------------------------------------- |
| `brace-expansion` | High   | CWE-400           | 서비스 거부(DoS) 공격. 조작된 입력으로 과도한 리소스를 소모시킬 수 있음. |
| `postcss`         | High   | CWE-22            | 경로 횡단(Path Traversal) 공격. `.map` 파일 로딩 시 임의 파일 접근 가능. |
| `vite`            | High   | CWE-22, CWE-522   | Windows 환경에서 NTLMv2 해시(비밀번호) 유출 가능성.               |

### 4. 해결 과정

#### 4.1. 자동 패치 적용

`npm audit fix` 명령어를 사용하여 SemVer 호환성을 유지하는 범위 내에서 취약점이 해결된 버전으로 자동 업데이트를 시도했다.

```bash
npm audit fix
```

이 명령을 통해 3건의 'High' 등급 취약점이 즉시 해결되었다. 이 과정에서 업데이트된 의존성 정보는 `package-lock.json` 파일에 반영되었다.

#### 4.2. CI/CD 파이프라인 반영의 중요성

CI/CD 환경(GitHub Actions)에서는 빌드의 일관성과 속도를 위해 `npm install` 대신 `npm ci`를 사용하는 것이 일반적이다. `npm ci`는 `package.json`을 참조하는 대신, `package-lock.json`에 명시된 정확한 버전의 패키지만을 설치한다.

따라서 로컬 환경에서 `npm audit fix`를 통해 `package-lock.json`을 갱신하고 이를 원격 저장소에 푸시해야만, CI/CD 파이프라인에서도 안전한 버전의 패키지를 사용하여 빌드를 수행하게 된다. 이 과정을 누락하면 파이프라인은 계속해서 취약한 구버전 패키지를 사용하게 되므로, `package-lock.json`의 커밋 및 푸시는 필수적인 후속 조치이다.

#### 4.3. 미해결 취약점 처리

`npm audit fix` 실행 후에도 `vite`와 `esbuild` 관련 일부 취약점은 "No fix available" 상태로 남았다. 이는 해당 취약점을 해결하기 위해 메이저 버전 업데이트가 필요하거나, 상위 의존성 패키지에서 아직 패치를 릴리스하지 않았기 때문이다.

이 경우, 강제로 버전을 수정하여 다른 패키지와의 호환성을 깨뜨리는 위험을 감수하기보다, VitePress 공식 릴리스에서 해당 의존성을 업데이트해 주기를 기다리는 것으로 결정했다.

### 5. 결론

정적 사이트일지라도 빌드 및 개발 환경의 보안은 중요하며, 주기적인 `npm audit` 점검은 필수적이다. `npm audit fix`를 통해 즉시 해결 가능한 취약점들을 패치하고, 변경된 `package-lock.json`을 원격 저장소에 반영하여 CI/CD 파이프라인의 보안 수준을 강화했다.
