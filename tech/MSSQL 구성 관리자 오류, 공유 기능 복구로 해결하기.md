# MSSQL 구성 관리자 오류, 공유 기능 복구로 해결하기


### 문제 상황: MSSQL 구성 관리자 실행 불가

운영 중인 서버에서 MSSQL 서비스의 네트워크 프로토콜, 시작 계정 등을 관리하는 핵심 도구인 **SQL Server 구성 관리자** 실행 시 오류가 발생하는 인시던트가 발생했다. 이 도구는 `mmc.exe`를 통해 관련 스냅인을 로드하는 방식으로 동작하는데, 이 과정에서 스냅인 로드에 실패하며 정상적으로 실행되지 않았다.

### 원인 분석: `sqlmanager.dll` 파일 누락

초기 분석 결과, 문제의 핵심 원인은 `sqlmanager.dll` 파일의 누락으로 파악되었다. 레지스트리에는 SQL Server 구성 관리자 스냅인에 대한 정보가 정상적으로 등록되어 있었으나, 스냅인 실행에 필수적인 물리적 DLL 파일이 존재하지 않아 로드가 불가능한 상태였다.

### 1차 시도: 수동 파일 복사의 한계

가장 먼저 시도한 해결책은 정상적으로 작동하는 다른 테스트 서버에서 `sqlmanager.dll` 파일을 복사해오는 것이었다. 그러나 이 방법은 실패로 돌아갔다. 에러 메시지가 변경되기는 했으나, 근본적인 문제가 해결되지 않았다.

이는 단순히 `sqlmanager.dll` 파일 하나만의 문제가 아니라, 해당 모듈과 연관된 수많은 종속성(dependency) 파일들이 함께 유실되었을 가능성을 시사했다. 관련된 모든 모듈을 수동으로 식별하고 복사하는 것은 비효율적이고 또 다른 오류를 유발할 위험이 커 이 방법은 부적절하다고 판단했다.

### 해결 전략: 설치 미디어를 이용한 '공유 기능' 복구

운영 서버의 서비스 중단을 피하기 위해, 원본 서버와 동일한 환경의 테스트 서버를 구축하여 안전한 복구 절차를 수립했다.

해결의 핵심은 **MSSQL 설치 미디어**에 내장된 복구 기능을 활용하는 것이었다. 특히, 데이터베이스 인스턴스 자체에는 문제가 없었으므로, 인스턴스에 영향을 주지 않고 관리 도구와 같은 공유 구성 요소만 복원하는 전략을 선택했다.

복구 절차는 다음과 같이 진행되었다.

1.  최초 MSSQL 설치 시 사용했던 ISO 이미지 파일을 마운트한다.
2.  설치 프로그램을 실행하고, 유지보수 옵션에서 '복구'를 선택한다.
3.  복구 대상을 선택하는 단계에서, 특정 데이터베이스 인스턴스가 아닌 **'공유 기능(Shared Features)'**만 선택하여 복구를 진행한다.

`SQL Server 구성 관리자`나 클라이언트 연결 도구 등은 특정 인스턴스에 종속되지 않고 서버 전체에서 공유되는 기능이다. 따라서 이 부분만 선택적으로 복구하면, 운영 중인 데이터베이스 엔진에는 전혀 영향을 주지 않고 문제의 관리 도구만 안전하게 재설치할 수 있다.

### 결과 및 결론

'공유 기능' 복구 작업은 성공적으로 완료되었으며, 이후 **SQL Server 구성 관리자**가 정상적으로 실행되는 것을 확인했다. 이 과정에서 운영 중인 MSSQL 인스턴스에는 어떠한 영향도 미치지 않았으며, 서비스 중단 없이 문제를 해결할 수 있었다.

이번 **트러블슈팅** 사례는 `dll` 파일 누락과 같은 구성 요소 문제 발생 시, 수동으로 파일을 조작하기보다 설치 프로그램이 제공하는 공식적인 복구 기능을 활용하는 것이 얼마나 안전하고 효율적인지를 보여준다. 특히 인스턴스와 **공유 기능**을 분리하여 접근하는 **MSSQL**의 복구 옵션은 서비스 안정성을 확보하는 데 매우 유용한 기능이다.
